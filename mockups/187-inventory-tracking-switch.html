Against the eight screens.md §0 checks

1. One jobScreen 1 is one row: see and change the tracking state. Screen 2 is one job: get an opening number for every box and product. Nothing else lives on either.
2. No paragraphsEvery row is an icon + name + one short line. The only sentence-length text is the off-state explainer and the "finish with what we have" note, each one line.
3. Icon on every row🔢 the switch row, 🍛/🌾/🥛 box or product rows, ✓ done, ℹ️ explainer notes.
4. ≤7 things on screenSettings row: 1 row. Count list: a progress bar + grouped tasks, scrolled, current task pinned in the footer so nothing competes with it. My tasks: existing task list pattern, counts fold into the existing per-day groups.
5. Fast, no on-open summarycounts.ts already tracks box levels and stocked-product on-hand; the list reads the existing count/level rows, it does not recompute a store-wide number on open.
6. A way back← Business / ← Today on every screen; the count list is reached from Settings (start), My tasks and the kitchen display (work it), never a fourth entry point.
7. One home per functionThe switch lives only on Settings → Business (screens.md §0's "one row" rule from #174); the count LIST has one home (its own screen) but appears through two doors (My tasks, KDS) — same task rows, not a duplicate screen.
8. As few screens as possibleOne new screen (the opening count list) and one existing-row change (Settings → Business); My tasks and the kitchen display fold the count tasks into their existing lists rather than adding a screen each.
