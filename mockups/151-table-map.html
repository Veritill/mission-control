Against the eight screens.md §0 checks

1. One jobSee every table's state and get to its check. Move and Split are reached from a table's own sheet, never a second screen with this job.
2. No paragraphsEvery tile is a table label, a seat count and a status word. The split/move sheets carry one sub-line each (12 words or fewer), nothing longer.
3. Icon on every row🍽️ table icon, 👥 seat count, a server avatar chip on occupied tables, 🔀 move, ✂️ split, ✓/− assignment boxes in Split.
4. ≤7 things on a phoneTopbar (back-free root tab) + Mine toggle, room chips (scroll), and one table grid = one job's worth of controls; each sheet (resume, move, split) is its own short list.
5. Fast, no on-open summaryTable state (open/occupied, total, minutes, server) is read off each check's own row the same way the register strip already holds it (`resolveCheck`, apps/api/src/checks.ts) — no recompute trip when the map opens.
6. A way backTables is the Register tab's own landing screen (pos-register.md §12: "folds into Register as a picker"), so it carries no back arrow itself, same as any root tab; every sheet's grabber/✕ returns to Tables, and the check screen it opens into (#135) already backs out here.
7. One home per functionSeating, resuming, moving and splitting a check each happen in exactly one place — this screen and its sheets — never duplicated on another page.
8. As few screens as possibleResume, Move and Split are three sheets over ONE new screen, not three new routes; the check itself reuses #135 rather than a second check screen. Table catalog editing (Settings → Tables) is a drawer on an existing settings page, not named here.
