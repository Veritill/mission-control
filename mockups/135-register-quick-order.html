Against the eight screens.md §0 checks

1. One jobBuild and manage the open check for this table. Pay/Discount/Split/Service charge/No sale/Search/Open item are all reached from here, never a second screen with the same job.
2. No paragraphsEvery row is a name, a number and an icon. The only sentence on the whole screen is the "sent to kitchen" toast, and it clears itself.
3. Icon on every rowEvery tile, every check line, every sheet action carries an icon (🍢 🫓 🥤, 🏷️ discount, ✂️ split, 🗄️ no sale, 💵 💳 tender).
4. ≤7 things on screenMain screen: back, seat pill, search, 6 category chips (scroll), a tile grid, one strip = one job's worth of controls. Each sheet (check, pay, discount, split, more, no-sale, open item) is its own short list, never everything at once.
5. Fast, no on-open summaryTapping a tile updates the strip and total from numbers already held in memory (resolveCheck, apps/api/src/checks.ts) — no recompute trip, no server round-trip to add a line; the check total is never computed fresh when the sheet opens.
6. A way back← at top-left names the parent ("Tables") and is one tap away on every sheet's grabber/✕; nothing here is a dead end.
7. One home per functionPaying, discounting, splitting and no-sale each have exactly one place to happen — this screen's sheets — not a duplicate on some other page.
8. As few screens as possiblePay, Discount, Split, Service charge, No sale and Open item are six sheets over ONE screen, not six new routes; Table map (the ← target) is the only sibling screen, folded in per pos-register.md §12, not a seventh.
