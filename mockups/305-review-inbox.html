Against the eight screens.md §0 checks

1. One jobLook at everything waiting for a confirm and clear it: read why, do the fix or dismiss it. Nothing else lives on this screen.
2. No paragraphsA row is one line (title + a truncated why) until tapped; the full why is still one sentence, never a paragraph. The fix is a single labeled button, never instructions.
3. Icon on every rowOne icon per kind (💰 cost, 📏 yield/prep yield, 🧑‍🍳 recipe confirm, 🧾 costability, 📥 onboarding ask, 🤖 agent event) plus a bad/warn color strip — same icon everywhere that kind of review appears (Cost check, Kitchen › boxes, Invoices already use these).
4. ≤7 things on screenCollapsed: topbar + severity pills + chip row + up to 5-6 rows before scrolling (2). Expanded: why + fix action + Done/Dismiss (3) — one row open at a time, others stay collapsed.
5. Fast, no on-open summaryEvery row and its severity/fix already rode on GET /reviews's own refresh (reviews.ts's adapters run before the list is read); the screen renders the rows it gets, it never recomputes a verdict itself.
6. A way back← at top returns to Work, named there; Review inbox is one tap from Work.
7. One home per functionThis is a SECOND door onto facts the seven surfaces (seal queue, import review, common-language review, pricing desk, cost check, yield check, golden merge) already own — those screens keep doing the deep work; this inbox is the one place to see everything open at a glance and clear the easy ones, never a competing editor.
8. As few screens as possibleOne screen, no drawer needed: the row itself expands in place for the fix, the same inline-expand pattern My tasks and Products already use.

Kind → icon → fix shape (matches reviews.ts today)

cost💰 — fix.kind is link (upload/open, with an "also: enter what you pay" for no-product), enter-cost, confirm (price still looks right), or none (made in house).
yield / prepyield📏 — fix.kind is link (open the box) or confirm (accept the measured ratio).
recipeconfirm🧑‍🍳 — fix.kind is always link (open the box; a chef confirms there).
costability🧾 — an invoice line missing a fact; fix.kind is link (open the line).
onboarding_ask📥 — the one thing that would unblock the most; fix.kind is link.
agent_dead🤖 — dismiss-only (fix.kind none): no in-product write exists yet for a stuck agent event.
common-language review, pricing desk and the seal queue keep their OWN screens (reviews.ts's own doctrine: "each screen keeps its own view") — they have no reviews-table adapter today, so this inbox names no chip for them rather than showing a filter with nothing behind it.
