Against the eight screens.md §0 checks

1. One jobThe home screen's one job is picking what to do next — every row states its own current state and links to the ONE place the work actually happens (Import review, Cost check, the register screen, Settings → Toast); it never re-renders that work here.
2. No paragraphsEach row is a title plus one short status line (a live count when there is one, a plain sentence when there is not); the "why" and the full what-happens/what-you-need/how-long text live behind the section's own detail screen (mockup #444's second page), never inline on this list.
3. Icon on every rowEvery section reuses an EXISTING meaning already in the product's own icon vocabulary (🏢 business, 👥 team, 🥬 products/catalog, 🏬 vendor, 🍳 kitchen, 📦 inventory, 🖥️ register, 🌐 commerce, 💰 money) — no new picture invented for this screen.
4. ≤7 things on screenSections are grouped into small cards of 2-3 rows each (mirroring the real checklistGroups shape today), so no single card ever shows more than 3 rows at once, even though 11 sections exist in total across the scroll.
5. Fast, no on-open summaryEvery status line reads a number GET /tenant/onboarding already computes (percent, costGap, openingCount, the outcomes) — nothing new is aggregated when this screen opens.
6. A way back← Settings on every state; this is the existing Getting started page, not a new screen.
7. One home per functionA section row is a link, never a second copy of the door it wraps — Your catalog links to Import review, Your vendors and invoices links to the vendor catalog screen and the review inbox, exactly as today's checklist rows already do.
8. As few screens as possibleZero new top-level routes: the eleven sections are rows/cards on the ONE existing Getting-started page; "Before day one" and "Go live" are cards at the top and bottom of that same page (D3's own recommendation), not new screens.
