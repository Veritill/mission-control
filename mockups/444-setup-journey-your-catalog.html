Against the eight screens.md §0 checks

1. One jobEach state has one action visible without scrolling: upload/Do it for me, or Review the N, or Open Products. The facts block never asks for a decision, it only sets expectations.
2. No paragraphsHappens/You need/How long are each one line; the "rough vs measured" note and the no-export alternative sit behind an ⓘ tap or their own small card, never a paragraph on the main flow.
3. Icon on every row🥬 the section's own icon (matches the Products tab and the home screen's row for this exact section), 📎 upload, 🤖 the agent, ✅ done, a spinner while working — no new picture invented.
4. ≤7 things on screenState 1: 3 facts + 1 drop zone + 2 buttons. State 2: 3 facts + 2 numbers + 2 links. State 3: 3 facts + 1 result + 1 button. Never more than about 7 elements on screen at once.
5. Fast, no on-open summaryThe 142/12 counts and the time estimate are the same numbers Import review and importEstimate.ts already compute — nothing new is aggregated when this screen opens.
6. A way back← Getting started on every state — this is a step inside the journey, never a dead end.
7. One home per functionReviewing items happens ONLY on the real Import review screen; this step links there rather than re-rendering the queue, exactly as setup-journey.md §3 requires ("it never re-renders their content").
8. As few screens as possibleNo new screen at all — this is a state of the existing Getting-started flow, reached by tapping a row, closed by the same back arrow every other section uses.
