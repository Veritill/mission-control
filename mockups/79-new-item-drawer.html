What changes (issue #79, Refs #54 — Kiran approved the fold):
  • apps/web/src/app/(app)/items/new/page.tsx (the routed form) is deleted; its fields and the POST /items call move into a small component (e.g. NewItemSheet.tsx) rendered as a bottom sheet, the same pattern as the invoice workspace's dock sheets (.ws-overlay family already in globals.css) or the confirm dialog (.dlg-overlay/.dlg).
  • "+ New item" on Products' topbar (items/page.tsx line ~183) opens the sheet instead of routing; the vocabulary fetch (GET /tenant) still runs once, on open.
  • On save, the sheet closes and the new item opens the same way a matched row does today (ItemDetailsPanel), not a route change — Products' list refreshes with the new row visible, never a separate created-item screen.
  • The canSee(uiKey('items','new')) permission gate is unchanged — same button, same guard, now opening a sheet instead of a link.
Screen checks this satisfies: #7 one home per function, #8 as few screens as possible (a sheet before a new screen — a five-field form never needed a route), #6 a way back (Cancel or tap outside, never a dead end).
