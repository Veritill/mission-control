Against the eight screens.md §0 checks

1. One jobTrack the cash in this drawer: open it, move cash out (pay-out/deposit), close and count it. Nothing else lives in this sheet.
2. No paragraphsEvery row is a label and a number. The only sentence-length text is the over/short explainer line, which is one line and only shows once counted.
3. Icon on every row💵 open/float, ➖ pay-out, 🏦 deposit, 🔒 close & count, plus a colored over/short badge (✅ even, 🔺 over, 🔻 short).
4. ≤7 things on screenNo-drawer state: float field + Open button (2). Open state: expected summary + 3 actions + a running list of today's moves (≤7 before scrolling). Each action (pay-out, deposit, close) is its own short sheet, never stacked together.
5. Fast, no on-open summaryExpected-in-drawer (float + cash sales − pay-outs − deposits) is carried forward from numbers the register already holds (checks.ts / resolveCheck totals, drawer ledger rows already in memory) — opening the sheet never triggers a recompute trip.
6. A way backThe grabber/✕ on every sheet returns to Register, named at the top; the drawer pill itself is reached from Register's header, never a separate route.
7. One home per functionOpening, paying out, depositing and closing the drawer each happen in exactly this one sheet — Day close (§7) only ever reads the result, it never re-opens or edits a drawer.
8. As few screens as possibleOne sheet with four short states (open / active / an action / close-and-count), not four screens; Pay-out, Deposit and Close are sub-sheets of this same drawer sheet, the same pattern #135's check sheet already uses for Pay/Discount/Split.
