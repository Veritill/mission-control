What changes (issue #78, Refs #54 — Kiran approved the fold):
  • apps/web/src/app/(app)/purchasing/[id]/page.tsx (the routed detail) is deleted; its data fetch (GET /purchase-orders/:id) moves to a lazy per-row expand on purchasing/page.tsx (fetched once on first open, cached, same drawer pattern used elsewhere — details.group in globals.css — but as a controlled expand so only one PO is open and the list never re-sorts under a tap).
  • Tapping a row's chevron expands its lines, reason text and vendor-constraint chip in place; a second tap, or opening a different row, collapses it — the list itself never scrolls or moves (screens §0 check 5).
  • "✓ Approve & send" stays exactly where it is today, now inside the open drawer, only for status === 'draft'; a sent/received PO's drawer is read-only, same as today.
  • No new route, no lost functionality — same API calls, same permission gates, one fewer screen.
Screen checks this satisfies: #7 one home per function, #8 as few screens as possible (a drawer before a new screen), #6 a way back (there's nowhere to go back FROM — the list is always visible).

This is a static mockup with example data only — no client data, no live calls.
